# 间歇停止更新问题排查

日期：2026-11-01。用户报告再次无法测量；排查后用户确认当前正常，刚才可能有杂音声源，原异常为偶发声音识别问题。

## 实际发现

旧版在两板时钟保持锁定、音频触发计数继续增加时，主板收到的对端测量事件停留在旧 ID 182，从板收到的结果停留在旧 ID 106。原程序每轮连续发送六个大 UDP 包，底层只有四个 RX 描述符；另一个确定缺陷是 low_level_output 忽略 HAL_ETH_Transmit 的错误返回，总是报告成功。

堆现场检查：1600 字节堆仍有约 1572 字节连续空闲，未证明发生堆耗尽。后续计数未见测量包分配失败或 CRC 错误。丢包与突发发送/处理阻塞相符，但未通过链路抓包独立证明每个丢包发生的位置。

## 修改

- 波形六片按至少 10 ms 间隔发送，最多三轮，不再一次突发六片。
- 主板结果按至少 40 ms 间隔重试，最多十次；从板回传对应的双事件 ID 确认；重复结果不重复入历史。
- 底层发送真实返回 HAL 失败状态，增加发送失败、分配失败、接收、CRC 和确认计数。

日志见 transport_early_master.log、transport_long_master.log、transport_long_slave.log。

## 未解决的边界

持续运行期间出现过远离主要距离分布的个别结果（如 69、80、2042 mm），用户确认可能存在其他杂音声源。当前跨板相关验证同一声音的时间差，尚未完整实现标准音频身份识别，因此不能把声音相关度高等同于声源几何条件正确，也不能声明所有杂音已被剔除。当前结论是传输连续性得到改善并经超过十分钟验证，偶发声源误识别仍需进一步验证和改进。
