# 双板测量协议

当前代码：Core/Src/app_measure.c。UDP 端口 50002，网络序，多字节整数使用大端编码。两板运行同一固件，由设备 ID 选举主从。

## 公共约定

Magic 为 0x4D455332，版本字节为 5。最后四字节是前面所有字节的 CRC32，反射多项式 0xEDB88320，初始值 0xFFFFFFFF，结束取反。

测量时间采用 AppClock 的统一时间基准。距离为声波到两个麦克风的路程差；在声源位于两板连线外侧延长线的任务摆放条件下，等于麦克风间距。声速通过手动设置或 DHT11 自动温度按 c = 331.3 + 0.606T m/s 修正；温度设置和有效读数通过 UDP 50003 共享。单点标定尚未实现。

## 波形片段：1056 字节，type=1

| 字节位置 | 内容 |
| --- | --- |
| 0 | Magic，4 字节 |
| 4 | 版本 |
| 5 | 类型 1 |
| 6 | 发送方主从角色 |
| 7 | 片段编号 0–5 |
| 8 | 本机声音事件 ID，4 字节 |
| 12 | 缓存首采样点统一时间 ns，8 字节 |
| 20 | 峰值，2 字节 |
| 22 | 包络起点相对缓存首点的 ns 偏移，4 字节 |
| 26 | 起点有效标记 |
| 27 | 保留 |
| 28 | 512 个 int16 PCM，1024 字节 |
| 1052 | CRC32，4 字节 |

每个事件有 3072 点，接收端以六位掩码确认完整性。只使用同一事件 ID 的完整缓存，不对缺片补零。片段依次发送，每片间隔至少 10 ms，最多三轮；主循环被显示刷新占用时会延后发送。事件的配对有效期为 500 ms。

## 测量结果：36 字节，type=2

Magic、版本后，字节 5 为类型 2，字节 6 为主板角色，字节 7 表示声源是否在主板侧。字节 8 为主板事件 ID，字节 12 为从板事件 ID，字节 16 为距离 mm，字节 20 为相关度千分数（2 字节），字节 22 为削顶标记，字节 23～26 为本次计算声速 mm/s（4 字节），字节 27～30 为相邻两次成功测量的绝对传播时差变化量 ns（abs(abs(dt_now)-abs(dt_previous))），字节 31 为是否已有上次参考，字节 32 为 CRC32。

主板计算一次结果供双方使用。从板仅接受与本机当前事件匹配的结果，并发回确认；重复结果只重发确认，不重复显示或计入历史。主板每隔至少 40 ms 重发，最多 10 次，收到匹配确认后停止。

## 结果确认：32 字节，type=3

Magic、版本与字节 5 的类型 3 后，字节 8 和 12 回传主、从板事件 ID，字节 28 为 CRC32。

## 匹配与拒绝

原始候选使用短包络门限，降低单采样噪声抢占。主板对波形一阶差分做归一化相关，并对峰值进行亚采样插值。变频参考音可直接以唯一相关峰定位；周期音脉冲出现多个近似载波峰时，利用整段 RMS 包络前沿的形状确定周期。前沿不存在、相关度不足、峰值不唯一或超出当前基础量程窗口时不更新结果。

界面无有效结果时，AMBIG 表示匹配不唯一，LOW 表示相关不足，RANGE 表示超出允许范围。持续单频纯音不保证能求出唯一距离。

## 调试与构建

IAR 工程 EWARM/LEDtest.ewp，配置 LEDtest。重新链接后必须运行 tools/make_history_macro.py，以当前 map 生成 SWD 地址；不得跨构建复用硬编码地址。

诊断含原始/有效事件数、收发及错误计数、结果确认计数、最近 32 条历史。连续运行测试应同时比较两板事件 ID、结果确认和历史增长，不能只以烧录成功或一次读数作为完成依据。
