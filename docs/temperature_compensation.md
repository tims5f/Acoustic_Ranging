# 温度补偿（2026-11-02）

## 功能与接线

已完成 DHT11 驱动、屏幕显示、手动设温、双板共享及测距补偿，IAR 编译 0 错误、0 警告，两个 ST-Link 对应板均已烧录同一版本固件。

LY-S0003 / DHT11：+ 接 5V，− 接 GND，S 接 Arduino A0（PA0）。PA0 采用数字模式，无 ADC、无内部上拉，仅开漏拉低；模块外部上拉负责释放总线。PA0 数字输入为 FT，符合本次 5V 信号条件。两板同一固件，不需要按传感器位置选择程序。

TIM5 运行于 1MHz；CH1、CH2 分别捕获 PA0 上升/下降沿，CH3 在 20ms 结束主机启动低电平，CH4 设置 7ms 接收超时。每 2.1 秒读一次，完成 40 位后停止捕获、主循环校验。无长时间忙等、无全局关中断。优先级 3 的短中断完成硬件时间戳记录，保留音频 DMA 的及时处理。

环境区显示当前温度、修正声速及 SENSOR A/B / MANUAL / SENSOR WAIT；−/+ 每次 0.5°C，调整即进入手动模式；AUTO/MAN 切换自动与手动。手动范围 −20～60°C。湿度目前只保留诊断读数，不参与声速公式。

## 共享与补偿

UDP 50003 每 250ms 交换温度和设置，含 CRC32；MASTER 优先使用自身有效传感器，否则选择 SLAVE 传感器。任一板的手动设置由 MASTER 统一应用，从板请求重复发送直到确认。有效样本超过 3 秒失效；自动模式没有有效温度时阻止新测距，可切换手动继续。

c = 331.3 + 0.606T m/s。测距结果包协议版本 3，字节 23～26 携带本次计算声速 mm/s；两板应一并升级。已有结果在五秒显示期内随温度按比例更新，每次从原始结果重算，避免累积舍入。

## 验证

- 主机测试 tools/test_temperature.py：实际 C 模块作为两个节点运行；验证传感器在 A/B、主板温度选择、从板手动设置、丢包后重发确认、自动恢复、样本过期、负温度及越界拒绝。
- tools/test_dht11_decode.py：使用厂家示例验证 24.4°C / 53%RH 帧、校验失败、−10.1°C 帧以及非法湿度/小数拒绝。
- 实板读取：初次连接板连续 33 次有效读取，0 校验错误、0 超时；后续从板记录连续 106 次有效读取，0 错误，自动显示所选共享温度 25.6°C。主从设备 UID 不同，均同步锁定。
- 通过 SWD 临时修改主板温度设置为 20.0°C 和 30.0°C，从板分别收到 20.0°C / 30.0°C、MANUAL 状态；随后已恢复 AUTO，并确认从板恢复 SENSOR A。
- 此次运行测距历史已递增到 10 次；未对这些声音事件的几何摆放和真值做确认，不能据此宣称测距精度达标。
- 原始日志位于 output/temperature/。尚需用户触屏交互验收、实测环境升温/降温、固定声源下温度变化对应距离变化的 ±2mm 验证，以及全量程测距精度验收。

DHT11 的绝对测温误差需要纳入报告中的温度误差预算；显示到 0.1°C 不表示具有 0.1°C 的绝对准确度。自动补偿功能完成与全量程精度验收应分别陈述。
